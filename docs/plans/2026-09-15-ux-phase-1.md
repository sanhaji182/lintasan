# UX Phase 1 Implementation Plan

> **For Hermes:** Execute with strict RED → GREEN → REFACTOR and independent review.

**Goal:** Ship a truthful Quickstart and task-oriented navigation without changing provider/routing state or redesigning the product.

**Architecture:** Pure TypeScript helpers own state derivation and route metadata; Svelte components render those states and call existing authenticated APIs. The landing page consumes public, non-secret health/catalog data and fails over to qualitative proof points.

**Tech Stack:** SvelteKit 5, TypeScript, Node test runner, Go embedded SPA.

---

### Task 1: Behavioral contracts
- Create `frontend/src/lib/quickstart.ts`, `navigation.ts`, and `landing-metrics.ts` interfaces through tests first.
- Test empty/configured/error Quickstart states, secret masking, model recommendation, snippet safety, nav route preservation/group defaults, and metric loading/verified/fallback states.
- Run `npm test`; verify RED from missing modules, then implement minimum helpers and verify GREEN.

### Task 2: Quickstart route
- Create `frontend/src/routes/dashboard/quickstart/+page.svelte`.
- Read existing connections, gateway keys, and callable models from existing APIs.
- Render five accessible steps, copy controls, language snippets, explicit empty/error states, key creation, and Playground handoff.
- Never reveal existing key material; only expose a newly created key from its one-time response.

### Task 3: Navigation and naming
- Refactor `Sidebar.svelte` around tested intent groups, preserving all routes.
- Keep primary/Gateway/Observability visible; collapse Manage and Advanced by default and auto-open for active descendants.
- Rename Providers to Provider Catalog and Accounts to Connections where they describe configured accounts.

### Task 4: Landing and accessibility
- Replace animated synthetic metrics with public verified values or qualitative fallback.
- Add loading skeletons, Skip to content, main target IDs, and visible focus styles.

### Task 5: Verification and release
- Run `npm test`, `npm run check`, `npm run build`, focused Go contracts, `go test ./...`, and diff/security checks.
- Obtain independent diff review; address blockers.
- Commit and push main, run `make build` then `make deploy`.
- Verify health/version/service logs, unauthenticated landing and API boundary, authenticated desktop/mobile UI, and document rollback artifact.
- Add structured evidence to the card and block as `review-required`.
